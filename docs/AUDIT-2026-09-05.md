# Orbit 0.6.0 candidate — audit and validation

Historical pre-acceptance checkpoint: local candidate, not committed, pushed, tagged,
or submitted to the marketplace. See [acceptance status](ACCEPTANCE-0.6.0.md) for the
subsequent user approval to commit and push.
Later live measurements and fixes are recorded in the
[performance report](PERFORMANCE-2026-09-05.md) and [0.6.1 release notes](RELEASE-0.6.1.md).
The previously uncommitted 0.5.1 work was preserved and reviewed; it was not treated as
proof that the requested behavior worked. Latest user requirements override the earlier
request to abandon snapping: live dragging is included again, without Main-and-stack.

## Agreed behavior

- Alt+Tab uses a fresh, session-frozen MRU list; quick switching chooses the last-used
  eligible window. Repeated/reverse input, release, cancellation, and exact-address
  focus must work without requiring an extra click.
- Include the active workspace on every connected display by default. Keep the picker
  on the primary display; focus the selected app in place. Optional all-workspace scope
  includes named ordinary workspaces, not hidden special workspaces.
- Show complete aspect-preserving window previews; never resize an app just to capture
  its thumbnail. Icons mode groups running windows by app and resolves installed icons.
- Preserve application fullscreen across switches, including browser video and local
  players. Hide compositor resize transitions until the destination is ready.
- This user's normal default is **Maximized / work-area filling**, `Super+Alt+F`.
  Keep manual tiling, floating/snapping, and true fullscreen available. Do not impose
  this personal preference on every Orbit installation or override dialog/PiP rules.
- Show the snap picker while a real window drag is still in progress at the top or a
  corner. Release over a zone to apply it; Escape or release outside cancels. Choices:
  halves, two thirds, thirds, wide center, quarters, Maximized, Fullscreen.
- Review the candidate before any GitHub push or marketplace submission. No social post
  or publication automation was changed in this audit.

## Confirmed defects and corrections

1. **Release-only drag bridge.** The old bridge only dispatched a generic shortcut
   after release. It could neither show a live picker nor reliably identify the dragged
   window after focus changed. The bridge now sends versioned, session-bound move/end/
   cancel events from Hyprland's real move controller, with the exact window and monitor.
   Release is delivered after native retile finishes, so retile cannot overwrite a snap.
   The click-through picker does not take the compositor's drag grab.
2. **Drag geometry and cancellation.** Work in logical monitor coordinates, including
   negative origins, fractional scale, rotation, reserved bar area, all four corners,
   and movement from the trigger into the picker. Reject stale sessions and drops on a
   different monitor. Escape suppresses reopening until the drag finishes.
3. **Wrong snap menu/actions.** Main-and-stack is removed. Maximized and Fullscreen are
   distinct explicit actions, with corresponding client state, not aliases for a snap
   rectangle. Disabled modes are omitted. Snap-group raising now uses Hyprland's valid
   `mode = "top"` Lua API instead of the invalid `top = true` argument.
4. **Async picker races.** Monitor, active-window, and client queries can complete in
   any order. The active window's monitor, not whichever query/focus arrived first,
   determines the target. Cancelled queries cannot reopen a modal picker.
5. **Fullscreen-to-fullscreen regression.** Restoring a new fullscreen window first
   lets Hyprland implicitly clear the old window's client fullscreen state. Reproduced
   with MPV. Orbit now explicitly releases the source's internal state with client state
   unchanged, then restores the destination, then focuses/raises it. The same sequence
   is used even when both windows want the same fullscreen mode.
   The final ordinary-Firefox test exposed a second race: a foreign-toplevel activation
   could overtake the compositor release and cancel real DOM fullscreen. That parallel
   activation channel is removed. The entire handoff now runs as one guarded Lua
   compositor transaction, reading live client state. Retries are idempotent and avoid
   Hyprland 0.56's toggle-prone `-1` keep-state sentinel. Native focus confirmation
   supplements the shell's asynchronous active-window cache.
6. **False frame-readiness proof.** Hyprland allocates its screencopy export at the new
   compositor geometry even if the client has not redrawn. Comparing screenshot sizes
   was therefore not a valid readiness check, and mixed-DPI coordinates made it worse.
   The native read-only readiness endpoint checks the current committed Wayland
   configure size against the requested size. QML checks address, mode, and activation
   generation, then uses a short reveal guard. A bounded fallback remains for unsupported
   or unresponsive clients. The transition cover is on the affected app's monitor,
   transparent outside an activation; the picker remains on the primary monitor.
7. **Lost/stale navigation.** Queue shortcut steps received during a commit and query
   fresh MRU state afterward. Drain a cancelled query before reopening. Tab cycles
   globally across grid pages; arrow navigation now reaches the view through its loader
   instead of referencing an out-of-scope QML ID. Modifier polling remains active after
   repeat keys, so losing a release event does not leave the picker stuck.
   Kernel-keyboard testing reproduced fast separate Alt gestures being merged. The
   first fix reported native Alt-release boundaries, but repeat testing caught a
   cross-channel race: the next Wayland global-shortcut press could arrive before the
   preceding socket2 release. The normal Hyprland binding now invokes a native Lua
   callback so presses, releases and Escape share one ordered socket2 stream. This
   retains compositor lock/inhibition/submap/repeat handling. The queue preserves each
   gesture and drains it against fresh MRU state. Delayed QML releases/modifier polls
   cannot prematurely commit a newer native gesture. Held Alt refreshes the watchdog;
   failed queries do not masquerade as release. Unloading the optional bridge restores
   the global-shortcut/modifier-query fallback.
8. **Named workspaces and stale state.** Negative IDs can represent normal named
   workspaces, not just special workspaces. Treat them correctly and prune closed-window
   fullscreen memories and snap groups even when the picker is closed.
9. **Personal defaults and icons.** Preserve Omarchy's stock default for fresh installs;
   retain this user's saved Maximized preference. Preserve deliberate floating/PiP
   exceptions. Theme icons use `image://icon/`, which the previous local-file-only color
   quantizer skipped. Sample those icons in memory for contrast and handle failed image
   loads with a monogram instead of a blank tile.
10. **Native build verification.** Preflight the complete compiler-visible Hyprland and
    dependency ABI, force a rebuild after header upgrades, and retain the plugin's exact
    runtime ABI rejection. No binary is safe to reuse blindly after a compositor upgrade.
11. **Return from media fullscreen.** Hyprland loses its previous-Maximized memory
    when Orbit temporarily releases internal fullscreen. A real app fullscreen-exit
    notification now restores this user's Maximized default through a guarded compositor
    transaction. It rechecks active address, current mode, mapping, floating and pinned
    state; it does not override manual tiling/drag commands or utility/PiP windows.
    Restoring an ordinary maximized app also synchronizes client state so future app
    fullscreen requests remain functional. Explicit client exits invalidate old memories.
12. **Exclusive-grab handoff race.** Repeated kernel-keyboard tests also proved that
    changing the picker's keyboard interactivity to None around its initial map could
    leave `omarchy-window-switcher` in Hyprland's exclusive-layer list. All focus retries
    were then refused. The grabbing picker is now explicitly unmapped at commit and
    the passive resize cover is a separate sibling window. Native traces confirm an
    empty exclusive-layer list during subsequent handoffs. This was a distinct defect
    from the input-channel ordering problem, not an additional arbitrary delay.

The test suite has 62 passing tests at this checkpoint. Native input, the real compositor,
screenshots, browser WebDriver state, and player IPC supplement—not replace—unit tests.
Browser tests used a generated, muted local video: first a separate temporary profile,
then a temporary private window in the ordinary Firefox process to validate real launch
and fullscreen requests. Existing user tabs were not navigated or closed. Evidence and
the pre-audit source/settings backup are stored privately under the local Orbit backup
directory, not in the release package.

Local troubleshooting can opt in to a bounded in-memory event trace with
`omarchy-shell orbit-diagnostics trace true`, read `orbit-diagnostics events`, and
disable/clear it with `trace false`. It contains switch events and window addresses,
not typed text or app contents; it is disabled by default and was disabled at handoff.

### Important test limitations

- Cua Driver could not reliably deliver/attest this host's Wayland input; failed or
  degraded Cua calls were **not counted as successful tests**. Native Wayland integration
  input exercised the compositor path. This is stronger than a synthetic picker event,
  but not a claim that a human physically dragged every app's custom titlebar.
- The required background launcher suppresses app fullscreen requests for launched test
  windows. Tests explicitly initialized only the disposable windows' fullscreen state
  and checked the real browser/player state before measuring Orbit transitions. The
  launcher itself and its protections were not changed. These tests alone were **not**
  sufficient evidence of normal Firefox behavior; the ordinary private-window test
  subsequently caught the activation race and verified the correction without forced
  initial fullscreen state.
- YouTube/Twitch/Vimeo/DRM players, every third-party app, XWayland renderers, monitor
  hotplug, and every rotated/mixed-DPI arrangement were not all exercised live. The fix
  is platform-level, not website-specific; the local HTML5 result is not a claim that
  all streaming sites have passed. Rotation and stale cross-monitor releases have
  automated coverage; all-corner physical tests used the scaled laptop display.
- The ordinary new-window and fullscreen-exit default were exercised live in Firefox.
  Other apps' launch and enabled-mode combinations have executable Lua/JS coverage but
  were not all launched individually. The immediate app-exit notification currently
  covers native Wayland apps, not XWayland.
- Windows retains independent overlapping window geometry; Hyprland's tiling compositor
  does not offer identical semantics. Orbit masks necessary handoff resizes rather than
  claiming they never happen. App-specific fullscreen-on-blur policies and internal GPU
  or web-content rendering are outside a universal compositor readiness guarantee.
- Kernel input is generated test input, not a claim that a person physically tried every
  keyboard or titlebar. Precise queued release/cancellation events require the native
  bridge; without it, the shell still uses the modifier-query fallback. Windows Edge
  tab enumeration and complete Windows Snap Groups are not implemented.

### Shell reload/shutdown incident

At 03:06:33 local time, Quickshell 0.3.1 crashed while an automatic local-plugin reload
overlapped the shell restart requested during deployment. The core's main thread was
creating a QML component after teardown had begun; executable debug symbols identify
`IpcHandler::updateRegistration` / `onPostReload` at the crash. Logs show plugin reload,
IPC deregistration and the exit request together. No OOM event was found (7.4 GiB
available); Hyprland and the user applications did not crash.

A reload/shutdown lifetime race is the evidence-backed interpretation, not a claim
that Orbit fixed an upstream Quickshell defect. Three standalone plugin reloads passed,
and subsequent deployments stopped the unlocked shell **before** replacing runtime
files, then restarted it after replacement. No further core was observed at that
checkpoint. The extracted temporary core was deleted; the system-managed report remains.
Do not race a development file hot-reload with an immediate shell shutdown. An upstream
fix/report is separate from this Orbit release and has not been submitted.

## Before release

Keep the candidate local pending review. On ordinary user-launched apps, confirm:

1. Drag your usual Firefox/T3/Codex titlebar (and Super+drag) to top/corners; the picker
   appears **before** release. Drop into Maximized/Fullscreen, then cancel another drag.
2. Quick/held/reverse Alt+Tab from both monitors; no lost switch or extra click. Test
   keyboard bursts and a window closing while the switcher is open.
3. New normal app → Maximized; real YouTube/Twitch or local player fullscreen → switch
   away/back → exit fullscreen. Check the desired work-area default on exit.
4. Hotplug/fallback display behavior and any XWayland apps you rely on.

Only after acceptance: review the final diff, commit/tag 0.6.0, push GitHub, then submit
the exact commit to the marketplace. Do not announce marketplace availability before
that exact snapshot is actually approved and published.
